MiniReto 6: formulario de reserva
En reservas.html agregue el formulario dentro de main y lo organicé en los
grupos "Tus datos", "Tu alquiler" y "Confirmación".

Elecciones de controles:
- Correo electrónico usa input type="email" para identificar el dato y permitir
  que el navegador compruebe su formato básico.
- Tipo de bicicleta usa opciones radio con el mismo name, porque se debe elegir
  una sola alternativa entre urbana, montaña y eléctrica.
- Recorrido guiado usa una lista desplegable porque permite elegir una opción
  entre ninguna y las tres rutas sin ocupar espacio con opciones siempre visibles.

Cada control tiene un id relacionado con su label mediante for y un name para el
envío. El formulario usa POST y apunta a reservas.html; el sitio es estático y
aún no tiene un servicio que procese las reservas.

MiniReto 8: auditoria de accesibilidad y contraste

Alcance: index.html, paginas/tarifas.html y paginas/reservas.html.
Se revisaron alternativas de texto, estructura de encabezados, nombres de
enlaces, idioma del documento y recorrido por teclado. Las tres paginas tienen
lang="es"; las imagenes informativas tienen textos alternativos descriptivos
(logo, bicicleta urbana y ruta ciclista), y la jerarquia de encabezados no
salta niveles. Las tablas usan caption y encabezados de fila/columna. Los
campos del formulario tienen etiquetas visibles y agrupaciones semanticas.

Hallazgo | Correccion
---------|-----------
No habia un mecanismo para saltar la navegacion repetida. | Se agrego al inicio de cada pagina el enlace "Saltar al contenido principal", que lleva al main enfocable.
La navegacion no identificaba cual pagina estaba activa. | Se agrego aria-current="page" al enlace actual del menu en cada pagina.
El foco de teclado dependia del estilo predeterminado del navegador. | Se definio un contorno de foco visible, de 3 px y con separacion, para enlaces y controles.
El enlace "Reservar ahora" no describia el objeto de la reserva cuando se escuchaba fuera de contexto. | Se cambio por "Reserva una bicicleta" en Inicio y Tarifas.
El enlace al mapa abria una pestana nueva sin avisar. | El texto visible ahora indica que el mapa se abre en una pestana nueva.
La posicion inicial del foco no permitia saltar al contenido principal. | Se asigno id y tabindex="-1" al elemento main de las tres paginas para que el destino del enlace de salto reciba el foco.

Prueba de teclado: desde el inicio de cada pagina, Tab muestra primero el enlace

las flechas para el grupo de opciones y activar la casilla con Espacio. No se

MiniReto 9: cascada, enlaces y foco

En cada pagina, la lista de navegacion tiene id="menu" y el enlace actual
recibe class="activo" y aria-current="page". En DevTools, la regla #menu a
prevalecia sobre .activo para el color: su especificidad es (1, 0, 1)
(un ID, cero clases y un elemento), mientras que .activo es (0, 1, 0)
(cero ID, una clase y cero elementos). Por eso la declaracion de color de
.activo aparecia tachada.

Se conservaron las dos reglas y se resolvio el conflicto con #menu a.activo,
cuya especificidad es (1, 1, 1); asi el enlace actual se distingue con verde,
negrita y subrayado sin !important ni estilos en linea. El menu usa fondo
crema para que el gris asfalto de #menu a tenga contraste suficiente. Los
estados hover y focus usan texto azul noche sobre naranja pedal.

Los enlaces "Reservar ahora" usan la clase .boton y tienen aspecto de boton,
con fondo verde y texto blanco; al pasar el puntero o recibir foco cambian a
fondo naranja y texto azul noche. Los campos del formulario muestran un
contorno verde visible al recibir foco.
El contenedor .campo tambien recibe un contorno con :focus-within como respaldo
para controles nativos, como la fecha, cuyo contorno puede variar segun el
navegador. Se conserva el contorno general para los demas elementos interactivos.

Verificacion: con la pestaña Styles de DevTools se compararon las reglas de
#menu a y .activo, la declaracion tachada y el selector de mayor especificidad.
El boton :hov permite revisar hover y focus; en las tres paginas se verifico
el recorrido por Tab y el indicador visible. Contrastes de texto pertinentes:
gris asfalto sobre crema 5.57:1; verde ruta sobre crema 4.93:1; azul noche
sobre naranja pedal 7.20:1; blanco sobre verde ruta 5.31:1.

Se aplico box-sizing: border-box a todos los elementos y pseudoelementos.
El contenido principal tiene max-width: 60rem y margenes automaticos; en la
portada de inicio usa min-height: 70vh. Los servicios ahora son tarjetas con
relleno, borde, esquinas redondeadas y separacion de la escala de espaciado.
Las imagenes ocupan el 100% del ancho interior de sus tarjetas. Las tablas
tienen celdas con relleno y bordes; sus encabezados usan Azul Noche con texto
Blanco para mantener el contraste. El formulario muestra las etiquetas encima

mantiene sus opciones en una fila.
